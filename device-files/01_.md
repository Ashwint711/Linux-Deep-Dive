### Device Files
    Everything in Linux is a file, thus all the devices in linux are presented as files on the system. 
    When we connect a new device like `Flash Drive` to the system then it is represented by a file under "/dev/usb".
    There are mainly 2 locations where we can find the device files and they are "/dev" and "/sys", to use a device user and programs use the path like "/dev/sda" and to get the characteristics/info of that device like:
    * Vendor name
    * Type, etc

#### Filesystem: Filesystem in Linux is set of rules and code to manage data in files and directories with operations like Create, Read, Write, Delete.
#### There are plenty of Filesystems in Linux, for example the primary filesystem `ext4`, now this file system is installed at a specific location on the disk drive and using which the user and system can access the disk drive easily.

#### Now theree are other filesystems like `devtmpfs`, `sysfs`, `procfs`, etc. Each has different purpose

### udev & devtmpfs
The major challenge with treating each device as files is the task of managing the /dev directory. In the earlier systems the users had to manually create a `device node` (device file) as they connect a new hardware using `mknod`
```
    mknod ...
```
But this can create inconsistency in the system, so to solve this we needed a auto tool which will handle this smartly on users behalf hiding the conplexity.

### udev
Udev is the solution to this problem, the new idea introduced was that the kernel knows when a new device is attached or a existing device is detached so the kernel will send an event to a user space process called `udevd` which after receiving the event will fetch the information of that hardware from the `/sys` and then create a `device node` under `/dev` path.
### But
This creates another problem and that is, we said that the `udevd` user process will create the device file after receiving event from the kernel, but where does this `udevd` program sits? Just like all other programs this also sits on a Disk which is managed by the filesystem of the system. Which is presented by `/dev/nvme0n1/p2`. Okay, but who created this device node? Hmm.. according the theory the `udevd` program created it but the path where it sits not even mounted to the path.

So, basically its a deadlock. Now to solve this he developer decided to devide this task in 2 parts:
* A continous running process creating `device nodes`
* And another pocess managing these `device nodes` after creation

The major focus point is that there is only one process active after starting the system after the boot loader loads kernel into the memory and that is the kernel itself. And the kernel is the program which only shuts off when the entire system is power off.
So the linux developers decided to handle the `device node` creation part in the `kernel` itself.

### devtmpfs
After deciding that when a new device will be connected to the system the kernel itself will go and create `device node` for that device. Now from starting the system till the point of shutting it off there can be some fixed devices like RAM, CPU, Disk, PORT, etc. But there are also devices which are attached to the system after turning on the computer like USB, Externel drive etc. So its clear that either we need to run the device creation process forever or trigger it when a new device is connected or a device is removed from the system. So linux developers choose to keep it running, and it sits under kernel and runs forever from starting the computer to shutting if off.

But then whats `devtmpfs`, so the `devtmpfs` is a special type of Filesystem, just like ext4, etc its a complete filesystem. This filesystem is mounted at `/dev` on the system. And this filesystem exists on in the RAM and all the files we see under `/dev` directory are actually coming from the ram and nothing is stored on the Disk at all.


### SCSI and Linux Kerlel
SCSI (Small Computer Systen Interface) - The traditional hardware setup is a host adapter linked with a chain of devices over an SCSI bus
In the older days the storage devices was connected to the computer with the help of a host adapter
`Host Adapter` is a controller which sits in the computer and its job is to make connection between computer and SCSI bus
```
computer <----> SCSI bus
```
